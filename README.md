# AD5 4.0 + NPC Forge RU 2.5.0 + Areas 1.3

Замените содержимое установленных скриптов AutoDamage, NPCForge и AD5Areas файлами из этой ветки. Не устанавливайте вторую копию AD5.
После перезапуска API выполните от GM:
```
!npc-fix --all
!ad5 buttons
!ad5 visibility
```
Дождитесь окончания ремонта NPC. Для проверки нажимайте способности заново: старые сообщения чата не обновляются.

## HP NPC
| Осталось HP | Маркеры |
|---|---|
| >75% | нет ранения |
| >50%, ≤75% | half-heart |
| >25%, ≤50% | half-heart + yellow |
| >0%, ≤25% | half-heart + red |
| 0 | skull |
У посторонних маркеров сохраняются значения и счётчики. HP NPC меняются только на токене; HP персонажа игрока — в листе и связанных токенах. Правила отображения HP игроков сохранены.

## Эффекты спасбросков
В поле эффекта спасброска (save_effect у NPC / savedesc в карточке) можно написать:
```
При провале: полный урон, оглушён, опутан. При успехе: половина урона.
```
Или для способности без урона:
```
При провале: опутан. При успехе: нет эффекта.
```
Также поддерживается явный «При провале: ...» в описании действия.
Пустое поле результата успеха, «нет эффекта» и «нет урона» означают нулевой урон и отсутствие состояний провала при успешном спасброске. Половина урона округляется вверх, как в предыдущем AD5.
Если способность содержит атаку и спасбросок, попадание обрабатывается с последующим спасброском; пустой результат успеха теперь означает отсутствие эффекта, а не игнорирование проверки.
Состояния применяются при провале к игрокам и NPC, в том числе нескольким целям и через Areas.

В JSON NPC Forge:
```json
{"name":"Путы","attack":false,"range":"20 фт круг","save":{"ability":"wisdom","dc":15,"onFailure":["оглушён","опутан"],"onSuccess":"none"}}
```
Это объект действия в массиве actions. onSuccess можно пропустить. Значения: half, none, full.
В !npc-add добавлен параметр --conditions|оглушён,опутан; --success можно пропустить.
Пример:
```
!npc-add --name|Путы --save|wisdom --dc|15 --conditions|опутан
```
Используйте обычные параметры выбора NPC вашей команды.

## Броски и история
Игрок может ответить кнопкой запроса или спасброском из листа D&D 5e 2014 (simple/npc/npcsave).
При нескольких одинаковых ожидающих проверках одного персонажа нужно использовать кнопку конкретного запроса.
NPC без управления игроками бросают автоматически. Запрос потребляется до изменения HP, повторный callback не применяет его снова.
Undo/redo восстанавливают HP и только добавленные этим эффектом маркеры. Уже существовавшие состояния не снимаются.
Если после применения HP или добавленный маркер изменились вручную, отмена останавливается, чтобы не затереть новые изменения.
Длительность состояний, иммунитеты и игровые последствия (помехи, запрет действий) остаются под управлением мастера: скрипт ставит маркеры.

## Проверка
Регрессионные проверки выполнены в JavaScript V8 с имитацией объектов Roll20: пороги HP, состояния, пустой успех, половина урона, спасброски из чата и листа, повторный callback, NPC auto-save, несколько целей, undo/redo, сохранение существующих маркеров, генерация карточки NPC без урона с метаданными площади, геометрия круга и конуса.
В живом Roll20 не запускалось. Имитация не воспроизводит sheet workers и браузерное управление шаблоном.
Повторить проверки: `node tests/regression.cjs`.
